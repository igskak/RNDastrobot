How do you move charts between astrology programs?

The file formats, what comes across, what does not, and where each program makes it easy or hard.

Export your charts from the old program as a file, then import that file into the new one. Names, birth data and places move reliably. Calculation settings, extra charts inside a record and your session history usually do not, so check those before you switch.

Switching programs is mostly an export and an import, and the part that decides whether it goes well is knowing in advance which formats the new program reads. Below, one section per source program, written from the way Steliara's own importer behaves, with the limits stated as plainly as the features.

What moves and what does not, from any program

Every chart file is a list of birth data. The name, the date, the local time, the place and its coordinates and the time-zone offset are the part that always travels, because every program needs them to draw a chart. Anything the new program calculates itself, such as house systems, orbs and chart styles, is rebuilt there, so it is not part of the transfer and should not be.

What gets lost is everything that was never in the file. Your calculation settings, the extra charts some programs save inside a record, the notebook beside the program, the folder of session documents and the recordings of past readings all stay behind unless you bring them by hand. Most people bring only the people they are still reading for, and that is a sensible way to do it.

From Astro.com

In your stored data on Astro.com, choose the AAF option and save the text as a .aaf or .txt file. Steliara reads both. The name, birth date and time, place, coordinates and the time zone come across, and so do the comments you saved against each chart, which become notes on the chart.

The AAF format has corners the importer does not cover yet, and it says so record by record rather than guessing: Julian calendar dates, some time types and some chart types are flagged as not supported. Those records are left out and the rest of the file is unaffected.

From ZET

ZET keeps its charts in .zbs database files. Export the database you want as a .zbs file and upload it. Each line becomes a chart with its name, date and local time, place and coordinates, offset from world time and comment, and the comment becomes a note on the chart. ZET does not record what kind of chart each entry is, so imported charts are saved as type Other and the review screen tells you so.

There is more on ZET itself, including why it has no browser version, on the Russian-language page ZET онлайн.

From Solar Fire and Astro Gold

The two programs share one chart file. Save your .SFcht file and upload it directly. The name, birth date and local time, place, coordinates and the UTC offset stored in the file come across, together with the notes you kept against each chart.

Two things are left behind and the review screen warns you about both. A Solar Fire record can hold subsidiary charts, for example a progression stored beside the radix. Only the main chart is saved, and you rebuild the others when you need them. The source program's calculation settings are not moved either, so the charts are recalculated with the house system and zodiac you pick during the import. Check those two choices before you confirm.

The reader accepts only the file layout it has been verified against, and anything else is refused with a message instead of being read loosely. The verification was done with Solar Fire 9 files. We have not tested a file saved by Solar Fire X itself.

From Solar Fire without a .SFcht file

Solar Fire can also send the whole chart database to a text file. Open the chart database, choose Send/Add, then Email All Charts, then Text File, and upload the charts.txt that results. The importer reads the header of each chart, its date, time and place, and the details text under it, which arrives as notes. As with .SFcht, calculation settings are not moved and are chosen again at import.

This is also the route to try first with files from Solar Fire X, since it does not depend on the binary file layout.

From Astrolog

In Astrolog choose File, then Other Formats, then Save Chart List, and upload the .as file. A single saved .as chart works too. The date, time, place and coordinates come across. Astrolog files carry no notes, so none arrive, and the importer is strict about Astrolog's time-zone and daylight settings: if it cannot read them without ambiguity, the record is flagged instead of being converted on a guess.

What the import does with your file

You upload the file in your account settings under Import charts and nothing is saved yet. A review table lists every record with its local date and time, its place and a status: ready, review needed or possible duplicate. Duplicates are checked inside the file and against charts you already have. A file can be up to 5 MiB and 2,000 records.

Then you choose where the charts go: each as a separate chart in your library, with shared tags if you like, or all together in one person's profile, new or existing. Large files can be paused and finished later, and an unfinished import is kept for 24 hours. When it is done you get a count of what was added and what could not be.

About times: the importer uses the UTC offset stored in the source file, not a guess from the place name, because the offset on the event date is the one that matters. Historical clock rules changed, and a file that already holds the right offset is the most reliable record there is.

Moving to somewhere else, and where it is easier than here

This page describes Steliara's importer because it is the one we can describe exactly, but the steps are the same for any move: export a file, check the new program's import list, import, then spot-check a few charts you know well.

Other programs do parts of this better. Solar Fire X has an import for its own library: choose Utilities, then Import Charts, Files, and Settings and select a folder or ZIP, which brings files and settings, not only charts (see Astrolabe's system requirements page). Astro Gold says its chart files are fully compatible and interchangeable with Solar Fire. Astrologer says you can paste chart data from Astro.com or Astro-Seek, and that its Practitioner and Professional plans offer a guided import of Solar Fire and AstroGold libraries. Steliara's list does not include Astro-Seek pasted data, and it does not move calculation settings, so a move between two Solar Fire programs is easier inside the Solar Fire family.

Sources, read on 3 November 2026: sfx.alabe.com/system-requirements, astrogold.io/get-astro-gold/for-macos, astrologerapp.org.

What no program moves for you

Your session history. Chart software was never built to hold what someone told you in March or what you answered, so no chart file contains it, and no importer can bring it across. In Steliara, the history starts when you begin recording a consultation with someone, with the audio recorded once both sides agree, transcribed and summarized onto their profile. Past sessions you kept in a notebook or a recording on your phone stay where they are until you add them by hand.

Questions

How do I move my charts from one astrology program to another?

Export them from the old program as a file, then import the file into the new one. Which formats work depends on the new program, so look at its import list first. Names, birth dates, local times, places and coordinates move reliably; calculation settings, extra charts stored inside a record and anything you recorded or wrote outside the chart file usually do not.

Which file formats can Steliara read?

ZET .zbs database files, Astro.com AAF files saved as .aaf or .txt, Solar Fire and Astro Gold .SFcht files, Astrolog .as chart lists or single charts, and the text file Solar Fire can send from its chart database. A file can be up to 5 MiB and 2,000 records.

Will my notes come across?

Notes you kept against a chart come across from ZET, Astro.com, Solar Fire and Astro Gold files, and from Solar Fire text exports, and land as notes on the chart. Astrolog files carry none, so there is nothing to bring. Notes you kept in a separate notebook, a document or a spreadsheet are not in any chart file.

Can I move my Solar Fire X charts?

The importer has been verified against Solar Fire 9 files and Solar Fire text exports. We have not tested a file saved by Solar Fire X itself, so with those, start from a text export or a file from an earlier version and check the first few charts.

Does the import change a chart's birth time?

It is built not to. It uses the UTC offset stored in the source file rather than guessing one from the place name, and a record it cannot read unambiguously is flagged and left out instead of being adjusted quietly. In Solar Fire, Astro Gold, Astrolog and Solar Fire text files, dates before 15 October 1582 are refused, because the calendar cannot be determined safely.

What happens with duplicates?

Possible duplicates are flagged before anything is saved, both inside the file and against charts already in your library, and charts that were already imported are marked as such. You choose what to keep.
