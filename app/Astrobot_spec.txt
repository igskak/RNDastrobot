Продакт-флоу.
Ты уже имеешь справочники и схему БД (ниже по документу), теперь вопрос: что за чем вызываем и какие модули нужны.
Ниже — бизнес-процесс подготовки данных для общего анализа гороскопа (то есть всех блоков плана, не только «Общий срез»).

0. Логика уровней
Удобно мыслить тремя слоями:
Геометрия — чистая астрономия: координаты, дома, аспекты. 
Математика над картой — силы, конфигурации, балансы. 
Смысловые агрегаты — общие срезы, психо-, тематический, кармический, опоры/задачи. 
Соответственно, бэкенд можно организовать в модули/скрипты:
astro_engine — расчёт карты (или внешний сервис). 
geometry_pipeline — сохранение планет/домов/аспектов. 
metrics_pipeline — силы, роли, балансы. 
analysis_general, analysis_psych, analysis_thematic, analysis_karma, analysis_support_challenge. 
Дальше — по шагам.

1. Ввод и нормализация базовых данных
Шаг 1. Ввод данных пользователя
Функция/эндпоинт:
create_birth_profile(payload) 
Действия:
Принимаем: date, time, timezone/offset, place (или координаты). 
Валидируем (формат, разумные диапазоны). 
При необходимости определяем координаты места (геокодер). 
Создаём запись в users и возвращаем user_id. 

2. Получение базовых координат (натальная геометрия)
Шаг 2. Расчёт натальной карты
Функция:
calculate_natal_chart(user_id) 
Внутри:
Собираем данные из users. 
Вызываем внешний/внутренний модуль astro_engine: 
astro_engine.compute(birth_datetime, lat, lon, house_system) 
На выходе: 
список планет с долготой, скоростью, ретро, 
куспиды домов, 
ASC, MC, узлы, Лилит/Селена, Фортуна (если движок умеет), и т.д. 

Шаг 3. Сохранение геометрии в БД
Функция:
persist_geometry(user_id, chart_data) 
Действия:
Заполняем natal_planets 
определяем sign по долготе, 
временно без силы/ролей. 
Заполняем natal_houses (12 строк). 
Заполняем angles. 
Заполняем natal_special_points (узлы, Лилит, Селена, Фортуна, Крест и т.п.). 
На этом этапе у тебя в БД есть «сырая карта».

3. Аспекты, конфигурации, стеллиумы
Шаг 4. Расчёт аспектов
Функция:
compute_aspects(user_id) 
Данные:
берём natal_planets + natal_special_points 
используем ref_aspect_types для углов и орбисов 
Действия:
Проходим все пары объектов (планеты/точки). 
Ищем, попадает ли разница долгот в орбис какого-либо аспекта. 
Пишем в natal_aspects с полями: 
aspect_type, orb, is_major, harmonic_type. 

Шаг 5. Конфигурации и стеллиумы
Функции:
detect_configurations(user_id) 
detect_stelliums(user_id) 
Действия:
По natal_aspects и правилам из ref_configuration_types ищем Т-квадраты, трины, йоды, кресты и т.п. → natal_configurations. 
По natal_planets ищем ≥3 планеты в одном знаке / доме → natal_stelliums. 

4. Сила, роли и интегральные балансы
Шаг 6. Расчёт сил и статусов планет
Функция:
compute_planet_strengths(user_id) 
Данные:
natal_planets, natal_houses, natal_aspects, natal_configurations, ref_sign_properties, возможно ref_planet_role_weights. 
Действия:
Для каждой планеты: 
смотрим знак → достоинство (обитель/изгнание/экзальтация/падение), 
учитываем дом (угловой/последующий/падающий), 
учитываем количество/тип аспектов, 
участие в конфигурациях/стеллиумах. 
Считаем strength_score. 
Ставим флаги special_roles (альмутен, Возничий, Дорифор, ручка ведра и т.п.). 
Обновляем natal_planets. 

Шаг 7. Интегральные балансы по карте
Функция:
compute_integral_balances(user_id) 
Данные: natal_planets, natal_houses, angles, ref_sign_properties.
Действия:
Подсчёт планет по стихиям/крестам/полу → user_element_balance, user_mode_balance, user_gender_balance, user_zones_balance. 
По домам/углам → 
user_hemisphere_balance, 
user_quadrant_balance, 
user_house_group_balance. 

Шаг 8. Космограмма Джонса
Функция:
compute_cosmogram(user_id) 
Данные: natal_planets.longitude, ref_cosmogram_patterns.
Действия:
Считаем распределение планет по кругу → natal_planet_distribution. 
Определяем тип фигуры (Bowl/Bucket/Locomotive/…) → cosmogram_pattern. 

5. Сборка блока «Общий срез»
Теперь готовим тот самый первый блок общего анализа.
Шаг 9. Формирование общего среза
Функция:
build_general_overview(user_id) 
Данные:
angles, natal_planets, natal_aspects, natal_configurations, natal_stelliums, 
user_element_balance, user_mode_balance, user_zones_balance, user_hemisphere_balance, user_house_group_balance, 
cosmogram_pattern. 
Действия по подпунктам плана:
ASC: 
берём знак/градус ASC, определяем стихию, крест, зону (из ref_sign_properties), 
находим планеты в орбисе соединения с ASC, 
находим управителя ASC (по знаку), его знак/дом/аспекты. 
Солнце и Луна: 
из natal_planets берём их знак, дом, 
из natal_aspects — аспекты к ним, 
собираем краткие сводки. 
Космограмма: 
из cosmogram_pattern берём тип, якорную планету, пустую дугу. 
Аспектные конфигурации и стеллиумы: 
выборка из natal_configurations и natal_stelliums основных фигур. 
Интегральные показатели: 
доминирующая стихия, крест, бинер, зоны, полусферы, квадранты, угловые/посл./падающие дома — из user_*_balance. 
Записываем всё одной записью в general_overview_summary.
На этом этапе у тебя полностью готов блок «Общий срез».

6. Психологический блок (в том же процессе)
Шаг 10. Психологический профиль планет
Функция:
build_psych_profile(user_id) 
Данные:
natal_planets, natal_aspects, 
психологические справочники: ref_planet_psych_functions, ref_planet_in_sign_psych, ref_planet_in_house_psych, ref_aspect_psych. 
Действия:
Для каждой планеты: собираем её знак, дом, аспекты. 
Тянем соответствующие описания из справочников. 
Собираем в user_planet_psych_profile. 

Шаг 11. Чакральный анализ
Функция:
build_chakra_scores(user_id) 
Данные:
natal_planets, natal_aspects, ref_chakra_mapping. 
Действия:
Считаем вклад каждой планеты в свою чакру (сила ± аспекты). 
Суммируем по чакрам → user_chakra_scores. 
По итоговым баллам определяем ведущие/слабые/блокированные. 

Шаг 12. Интегральный психосрез
Функция:
build_psych_summary(user_id) 
Данные:
user_planet_psych_profile, user_chakra_scores, user_element_balance, user_mode_balance. 
Результат:
заполняем user_psych_summary. 

7. Тематический анализ
Шаг 13. Анализ домов/сфер
Функция:
build_house_thematic_summary(user_id) 
Данные:
natal_houses, natal_planets, natal_aspects, ref_house_meanings. 
Действия:
Для каждого дома: 
знак на куспиде, включённый знак, управитель (его знак/дом/аспекты), 
планеты в доме и их аспекты, 
сигнификаторы темы (по ref_topic_significators, если дом входит в какую-то тему). 
Запись в house_thematic_summary. 

Шаг 14. Выделение ведущих тем жизни
Функция:
build_life_themes_summary(user_id) 
Данные:
natal_planets (дом Солнца, силы), 
natal_stelliums, 
house_thematic_summary. 
Результат:
подсчёт сильных/слабых домов, дома Солнца, дома стеллиумов → life_themes_summary. 

Шаг 15. Темы: здоровье, карьера, отношения, семья, духовность
Функция:
build_topic_summaries(user_id) 
Данные:
house_thematic_summary, 
life_themes_summary, 
ref_topic_significators, ref_topic_house_weights. 
Результат:
topic_health_summary, 
topic_career_summary, 
topic_relationships_summary, 
topic_family_summary, 
topic_spirituality_summary. 

8. Кармический блок
Шаг 16. Узлы, Сатурн, Лилит/Селена, Фортуна, Крест
Функции:
build_nodes_summary(user_id) → user_nodes_summary 
build_saturn_summary(user_id) → user_saturn_summary 
build_lilith_selena_summary(user_id) → user_lilith_selena_summary 
build_fortune_fate_summary(user_id) → user_fortune_fate_summary 
Каждая функция берёт соответствующие точки/планеты + их аспекты и тянет интерпретационную «семантику» из кармических справочников.

Шаг 17. Кармический статус планет
Функция:
build_planet_karma_status(user_id) 
Данные:
natal_planets (баллы, достоинства, дома), 
natal_aspects (напряжённость/гармоничность), 
natal_configurations, 
user_nodes_summary, 
user_lilith_selena_summary, 
ref_karma_status_rules. 
Действия:
Прогоняем правила из ref_karma_status_rules по каждой планете. 
Определяем статус: талант / задача / опора / проблема. 
Записываем в user_planet_karma_status. 

Шаг 18. Общий кармический срез
Функция:
build_karma_summary(user_id) 
Данные:
узлы, Сатурн, Лилит/Селена, Фортуна, статусы планет. 
Результат:
user_karma_summary. 

9. Блоки «На что опираемся» и «Что прорабатываем»
Шаг 19. Опорные факторы
Функция:
build_support_profile(user_id) 
Данные:
natal_planets (сильные планеты, в обители/экзальтации, в 1 доме, Возничий), 
natal_stelliums, 
natal_aspects (трины, гармоничные соединения), 
user_nodes_summary (Южный Узел + диспозитор), 
user_lilith_selena_summary (Белая Луна), 
ref_support_sources. 
Результат:
user_support_factors (по каждому источнику опоры), 
user_support_summary. 

Шаг 20. Факторы задач и проработки
Функция:
build_challenge_profile(user_id) 
Данные:
natal_planets (баллы < -3, изгнание/падение), 
user_nodes_summary (Северный Узел + диспозитор), 
natal_planets.special_roles (Дорифор), 
user_lilith_selena_summary (диспозитор Лилит), 
natal_aspects (квадратуры, оппозиции), 
ref_challenge_sources. 
Результат:
user_challenge_factors, 
user_challenge_summary. 

10. Выход: готовый «общий анализ»
После выполнения этих шагов у тебя:
заполнены все «геометрические» таблицы, 
посчитаны силы, роли, конфигурации, балансы, 
построены все агрегаты по блокам. 
Дальше любой API-эндпоинт типа:
GET /users/{id}/analysis/general 
GET /users/{id}/analysis/psychological 
GET /users/{id}/analysis/thematic 
GET /users/{id}/analysis/karmic 
просто читает уже готовые таблицы (*_summary + детальные профили) и кормит это в текстовый генератор/бота.
То есть вся «тяжёлая математика» и бизнес-логика идут один раз на этапе подготовки данных, а не при каждом запросе гороскопа.



Начнём с цельной картины, а потом разложим бэкенд-процесс как конвейер.

1. Общая архитектура
Цель:
БД и бэкенд, которые из сырых астроданных (как в твоём примере) готовят структурированный набор слоёв:
Общий срез 
Психологический гороскоп 
Тематический анализ 
Кармический блок 
Блок «На что опираемся» 
Блок «Что нарабатываем / прорабатываем» 
Дальше уже любой «астро-бот» может брать эти слои и собирать интерпретации.

3. Бэкенд-процесс подготовки данных
(для общего плана анализа гороскопа)
Опишу как конвейер шагов: от входа до того, что все таблицы заполнены.

3.1. Вход
На вход приходит:
дата рождения 
время рождения (с таймзоной или местным временем + зона) 
место (координаты) 
Бэкенд:
нормализует время (UTC, локальное, поправка на летнее) 
считает юлианский день (при необходимости) 
отдаёт эти данные внешнему астрологическому движку (или своему модулю), который возвращает: 
долготy планет 
куспиды домов 
ASC, MC, Vertex и т.п. 
фиктивные точки (если считаются движком). 

3.2. Этап 1 — запись базовой геометрии
Создать запись в users. 
Записать в: 
natal_planets (все тела с долготами, знаком, домом, ретро, скоростью) 
natal_houses (12 строк для домов) 
angles 
natal_special_points (узлы, Лилит, Селена, Фортуна и т.п.) 
На основе ref_sign_properties сразу проставить: 
element, mode, dignity планет 
house_group для домов. 

3.3. Этап 2 — вычисление производных: аспекты, конфигурации, стеллиумы
По natal_planets и natal_special_points рассчитать аспекты → заполнить natal_aspects. 
На основе аспектов: 
выявить конфигурации (Т-квадраты, трины, йоды и т.д.) → natal_configurations 
определить стеллиумы по дому/знаку → natal_stelliums 
Вычислить «распределение планет по кругу» → natal_planet_distribution 
Определить фигуру Джонса по ref_cosmogram_patterns → cosmogram_pattern. 

3.4. Этап 3 — сила и статус планет ✅ РЕАЛИЗОВАНО
На основе:
ref_sign_properties (достоинства)
положения в домах
угловости домов
участия в конфигурациях
рассчитать strength_score для каждой планеты → обновить natal_planets.
Отметить специальные роли:
альмутен карты
Возничий
Дорифор
король аспектов   → заполнить special_roles в natal_planets.

СТАТУС РЕАЛИЗАЦИИ (дата: 2025-11-28):
✅ Реализован расчет силы планет (strength_score) на основе:
   - Достоинств (обитель/экзальтация/изгнание/падение)
   - Положения в домах (угловые/последующие/падающие)
   - Участия в аспектах
   - Участия в конфигурациях
✅ Реализовано определение специальных ролей:
   - Альмутен карты (самая сильная планета)
   - Возничий (планета перед Солнцем)
   - Дорифор (планета после Солнца)
   - Король аспектов (планета с наибольшим количеством аспектов)
✅ Данные сохраняются в таблицу natal_planets (поля strength_score и special_roles)

3.5. Этап 4 — интегральные балансы
По natal_planets:
посчитать стихии, кресты, бинер → user_element_balance, user_mode_balance, user_gender_balance, user_zones_balance. 
По знакам и долготам:
полусферы, квадранты → user_hemisphere_balance, user_quadrant_balance. 
По домам:
угловые/последующие/падающие → user_house_group_balance. 

3.6. Этап 5 — формирование «Общего среза»
Используя всё выше:
ASC-блок: 
из angles + ref_sign_properties → знак/стихия/модальность/зона ASC; 
поиск планет в соединении с ASC по natal_planets; 
определение управителя ASC и его аспектов по natal_aspects. 
Солнце и Луна: 
из natal_planets → знаки, дома, аспекты; 
собрать краткое резюме по светилам. 
Космограмма: 
из cosmogram_pattern → тип, якорная планета. 
Конфигурации и стеллиумы: 
взять ключевые элементы из natal_configurations, natal_stelliums. 
Интегральные показатели: 
из всех user_*_balance таблиц. 
И всё это записать одной строкой в general_overview_summary.
На этом этапе у тебя полностью готов блок «Общий срез» для общего плана анализа.

3.7. Этап 6 — психология
Используя:

На основании профилей и балансов собрать интегральное резюме → user_psych_summary. 

3.8. Этап 7 — тематический анализ
Для каждого дома:

На основе сил домов, стеллиумов, дома Солнца: 
альмутен, ведущие дома → life_themes_summary. 
На основе ref_topic_significators и ref_topic_house_weights: 
создать topic_health_summary, topic_career_summary, topic_relationships_summary, topic_family_summary, topic_spirituality_summary.

Аггрегировать:
