# Полная редактура немецкого каталога

Дата: 2026-09-14. Исходная база: main 52ac5240, точный SHA256 в review-ledger.json.

Проверены все **2303 ключа** исходного frontend-каталога, а не выборка. Поскольку полного немецкого файла не было, подготовлен **de.editorial.json**: немецкий перевод всего каталога, затем отдельное чтение всех немецких строк без исходника и сверка спорных мест с контекстом. На повторном проходе сделано 38 дополнительных правок; они записаны в editorial-revisions.json. Обращение — Sie.

Это редактура моделью. Проверка носителем языка и визуальная проверка в работающем немецком интерфейсе не проводились. Файл находится в документации и не подключён к приложению. Тексты вне этих 2303 ключей, включая новые ключи из будущего извлечения хардкода, переводятся отдельно по PLAN.md. Письма и API errors находятся в COPY_GUIDE.md, а не в frontend-каталоге.

## Что передать исполнителю

- `de.editorial.json` — полный вложенный каталог, повторяющий текущий keyset en.json. Использовать как готовую основу, не переводить заново.
- `review-ledger.json` — все 31 пакета с перечнями проверенных ключей и SHA256 результата.
- `editorial-revisions.json` — 38 изменений второго редакторского прохода с причиной.
- `identical-values.de.json` — 168 проверенных точечных совпадений en/de. Это имена, нормальные немецкие термины, символы, параметры и намеренно пустая строка; не 168 недопереведённых текстов. Перенести только точные исключения de, не расширять глобальную allowlist.
- `source-repairs.en.json` — предложенное восстановление 27 английских заглушек по содержательному русскому источнику. Плоская карта ключей для merge; не замена всего en.json.
- `integration-additions.de.json` — два дополнительных ключа: название немецкого языка и форма единственного числа для прошедшего события. Добавить их вместе с использованием и эквивалентами в других локалях.
- `verify_catalog.py` — повторяемая структурная проверка артефакта. Запуск из корня репозитория: `python3 docs/i18n/de/verify_catalog.py`.

## Исправления и обязательные условия интеграции

### 1. Двадцать семь английских заглушек

`page.forecast.help.sections.*` содержит Text1/Text2/Title/Item1 вместо справки. Полноценный источник найден в ru.json. Немецкий текст восстановлен по нему, включая три пары `<strong>`; соответствующий список ключей записан в ledger. Чтобы базовый en снова был содержательным и HTML-проверка оставалась строгой, подготовлен source-repairs.en.json.

Одна сознательная смысловая правка: RU `page.forecast.help.sections.tips.item4` обещает «интерпретацию» в чате, хотя действующий ассистент и `page.index.faq.items.four.a` оставляют интерпретацию астрологу. В немецком и предложенной английской правке — вопросы о найденных событиях, без обещания AI-деутунга. При реализации согласовать этот текст и в RU/UK. Саму AI-политику не менять.

Часть этой справки относится к старым экранам; не восстанавливать удалённый UI ради ключей. Каталог переведён целиком, даже если строка сейчас не показывается.

### 2. Единственное число и параметры

В `clients.js:buildSolarAlertRow` дни 0/1 уже обрабатываются отдельно как Today/Tomorrow. `daysUntil` поэтому корректно остаётся `in {days} Tagen` для days > 1. Для прошлого дня обработчика нет: `passed` выдаст `vor 1 Tagen`.

В integration-additions.de.json подготовлен `page.clients.alerts.passedOne = vor {days} Tag`. При abs(days) === 1 выбирать этот ключ, при остальных — прежний passed. В другие каталоги добавить эквиваленты. Это необходимая небольшая правка вызывающего кода; её нельзя исправить корректным единым переводом существующего шаблона для любого числа без неестественной фразы.

Для универсальных счётчиков Horoskope и summary.timelineReady в основном черновике использованы естественные для метрики конструкции `Horoskope: {current}` и `Prognoseereignisse in diesem Zeitraum: {count}.` — они грамматически корректны при 0/1/2 без изменения runtime.

У timeline уже есть one/other: сохранены `Vor {days} Tag exakt` и `Vor {days} Tagen exakt`, а также соответствующие будущие формы. Проверять подстановкой 0/1/2, а не только placeholder regex.

### 3. Заголовок гостевой консультации

В consultation-join.html заголовок склеивается из sessionWith и имени. JS подставляет общий fallback `Ihre Astrologin oder Ihr Astrologe`, который также используется отдельно. С предлогом mit требовался бы другой падеж.

В черновике: `Beratung:` + `Anna` либо `Ihre Astrologin oder Ihr Astrologe`. Это сохраняет естественный заголовок без новой логики склонения. guide переведён как роль `Astrologin / Astrologe`, а не абстрактное «руководство».

### 4. Астрологическая терминология

- `elevated` — **eleviert**, а `exaltation` — **Erhöhung**. Это разные понятия; проверено по реализации find_elevated_planet и [Astrodienst: Elevation](https://www.astro.com/astrowiki/de/Elevation).
- Jones: **Streuform**, **Spreizform**, Schale, Eimer, Bündel, Lokomotive, Wippe. Spreizform сверена по [Astrodienst: Horoskopmuster nach Marc Edmund Jones](https://www.astro.com/astrologie/in_jonespatterns_g.htm?lang=j).
- Для Chariot и Open_Envelope сохранены отдельные названия: `Wagen (geschlossener Briefumschlag)` и `Offener Briefumschlag`. Геометрия сверена с seeds/05_configuration_types.sql. Не сливать их с Mystic_Rectangle только из-за сходного имени; термин Briefumschlag также встречается у [Astrodienst](https://www.astro.com/astrowiki/de/Briefumschlag).
- jubilee/middle обозначают критические градусы: **Jubiläumsgrad / Mittelgrad**, а не праздник/середину интерфейса. Названия специфичны для методики проекта.
- У редких авторских конфигураций перевод описывает исходную фигуру. Он не выдаётся за единственный общепринятый термин всех немецких астрологических школ.

### 5. Названия настроек и числа

Chart presets сохраняют не только расположение панелей, поэтому **Konfiguration**. Panel editor layout — **Anordnung**. Apply в настройках — **Übernehmen**, выполнение команды — **Anwenden**. `chart` переведён как Horoskop, а в графике динамики — Diagramm.

Десятичная запятая используется в обычном тексте. Но `page.forecast.table.filters.maxOrbPlaceholder` сохранён как `z. B. 3.5`: рядом числовой ввод и существующий parser. Не менять формат числовых данных по форме надписи. TT.MM.JJJJ — только переведённая подпись, код значения DD_MM_YYYY остаётся прежним.

### 6. Содержательные противоречия исходника

Они выявлены, но не исправлены догадкой о продукте:

- `page.login.fields.accountType.trial.badge` обещает 5 charts, а `page.plan.descriptions.trial` — unlimited charts.
- Публичный pricing использует Practitioner/Studio, а внутренние статусы — Beginner/Standard/Pro.
- `page.accountSettings.limits.copy` говорит, что Orbs/цвета пока отсутствуют, хотя в том же каталоге уже есть соответствующие настройки.
- Часть onboarding-вопросов просит темы/значения/динамику отношений, тогда как описание ассистента ограничено данными.

В черновике эти строки переведены по исходному смыслу; коммерческие условия, доступность и policy не перепридуманы. Перед выпуском исполнитель должен проверить живой UI и актуальные entitlement/settings paths и согласовать копирайт всех языков с фактическим поведением. Это отдельные замечания о содержании исходника, а не незавершённый перевод.
