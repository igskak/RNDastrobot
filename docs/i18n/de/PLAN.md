Основа: `swisseph`, `main`, commit `52ac5240` (полный hash в translation-source.json).

## 1. Результат и границы

Добавить полноценный немецкий язык в действующий продукт Steliara: публичные страницы, регистрация/вход, письма, рабочее пространство, настройки, клиенты, карты, прогнозные таблицы/таймлайн, календарь, консультации и ассистент. Перевести существующий смысл, без изменения возможностей, цен, юридических условий и астрологических расчётов.

- Код языка `de`, подпись `Deutsch`, краткая `DE`, `html lang="de"`.
- Региональный формат `de-DE`; `de-DE`, `de-AT`, `de-CH`, `de_DE` нормализуются в `de`. Отдельные австрийский и швейцарский словари не нужны.
- `en` остаётся базовым каталогом и fallback. Немецкий не становится глобальным default.
- Профессиональное обращение `Sie/Ihnen/Ihr`, глоссарий и образцы в COPY_GUIDE.md.
- Не переводить имена клиентов, заметки, исторические сообщения, названия пользовательских карт, идентификаторы объектов/API/tool calls, IANA timezone IDs, SQL entity keys.
- Консультационный отчёт остаётся на языке разговора. Немецкий UI не превращает русскую консультацию в немецкую автоматически.
- Demo/styleguide, внутренние логи, комментарии и удалённые экраны не входят в объём.
- Немецкий SEO с отдельными URL/hreflang/SSR — отдельный проект. Перевод видимого контента существующих публичных страниц входит сюда.

## 3. Решения по архитектуре

### Существующий i18n

Расширить нынешний runtime, без новой библиотеки, системы namespaces или сборщика переводов. `de.json` должен повторять вложенную структуру en, а не быть плоским словарём. Загрузка уже идёт через `/locales/{locale}.json?v={buildId}`; специальный роут не нужен.

В built-in bootstrap-каталоге i18n.js добавить минимальный немецкий блок по образцу остальных. `locale.name.de` добавить в четыре каталога и встроенные подписи (`German`, `Німецька`, `Немецкий`, `Deutsch`). Для немецкого locale.name.en/uk/ru: `Englisch`, `Ukrainisch`, `Russisch`.

app-nav: использовать runtime.SUPPORTED_LOCALES, когда доступен; небольшой fallback-массив допустим для загрузки без runtime. Перенести собственные user-facing LABELS в существующие каталоги (новые page.nav.* только где нет подходящего ключа), сохранив английский bootstrap fallback. Не создавать общий генератор Python/JS реестров ради четырёх языков. Ранний inline preloader может сохранить свой маленький список; добавить проверку согласованности.

### Приоритет и сохранение языка

Не менять незаметно существующие политики:

- frontend: query → localStorage/cookie → browser → en;
- API: найденный user preference → explicit query/header → Accept-Language → en;
- auth mail: explicit locale → astrologer.preferred_locale → request context/headers → en.

В API dependency читается таблица `users`, а `Astrologer.preferred_locale` хранится в `astrologers`. Это существующий разрыв, а не повод проектировать новую синхронизацию аккаунта в этой задаче. Добавить de в существующее поведение и тестировать каждый путь отдельно. Не обещать синхронизацию выбора языка между устройствами. Регистрация/повторное verification уже сохраняют предпочитаемый язык; глобальный переключатель сохраняет локально.

parse_accept_language сейчас включает q=0 в кандидаты. При расширении resolver добавить узкое исправление в Python/JS: нулевой вес исключается, недопустимые веса не становятся предпочтительными; регрессионные тесты фиксируют поведение. Неподдерживаемый `fr` подходит для теста fallback; прежние тесты с `de` как неизвестным языком заменить.

### Даты, числа, данные

Добавить `de` → `de-DE` в LocaleFormatters. Проверить 24-часовое время, десятичную запятую, названия месяцев, сортировку. Явно выбранные пользовательские DD_MM_YYYY/MM_DD_YYYY/YYYY_MM_DD приоритетнее языка. В режиме LOCALE дата формируется через Intl; не требовать ведущие нули без явных options.

Не превращать `12.5` в `12,5` в JSON/числовых input/API. Не менять часовой пояс по языку: de не означает Europe/Berlin. `en-US` в timezones.js может использоваться для технического разбора; не заменять массовым поиском.

### AI и консультации

Действующий путь: `api/routes/assistant.py` → `AstroAssistantService.chat(locale=...)` → `_locale_instruction` → при необходимости `astro_narrative.narrate(locale_line=...)`.

- Добавить German в `_LOCALE_LANGUAGE`; формальное Sie в немецкую инструкцию.
- Сохранить текущую политику: язык UI по умолчанию, явно другой язык последнего сообщения может его переопределить.
- `_wheel_view_reply`, `_refuse_and_redirect` сейчас делают бинарный выбор кириллица/английский. Передать locale по их вызовам через существующий метод финализации и локализовать готовые ответы. Для de использовать Sie; не внедрять ненадёжный «определитель немецкого» по одному латинскому слову.
- Аудировать `_MULTI_WHEEL_INTENT_RE`, `_SINGLE_WHEEL_INTENT_RE`, `_ADD_LAYER_VERB_RE`, `_LAYER_METHOD_INTENT_RE`, распознавание согласия/предложений и связанные детерминированные ограничения. Они защищают смысл команд, а не просто помогают переводу. Немецкие запросы не должны создавать слой вместо смены вида.
- Тестовые фразы: «Wechseln Sie zur Einzelansicht», «Zeigen Sie mehrere Horoskopringe», «Fügen Sie einen Transit hinzu», «Ja, bitte», «Zeigen Sie die Transite für das nächste Jahr». Проверить actions и аргументы, а не только язык текста.
- tool names, JSON schema keys, enum values, provenance/citation IDs сохраняются.
- В consultation.js нормализовать session.language через существующий normalizer (de-DE тоже допустим), setLocale(..., persist:false). Сохранить исходные report/summary/transcript.
- consultation_summary.py/openai_service.py уже требуют язык разговора; добавить немецкие fixtures, не переписывать промпты целиком. TranscriptionService использует language_detection=True — не фиксировать German для всех записей.

### База и справочники

Не делать миграцию 017 обязательной частью первого PR. В текущем дереве reference_lookup.py не имеет найденных вызывающих мест; старые natal/prognostic interpretation tables удалены миграцией 027. astrologers.preferred_locale — String(8), отдельный schema change для de не требуется.

Если при проходе живых экранов обнаружен вывод человекочитаемых справочных полей из БД: сначала зафиксировать точный route → service → field → UI. Идентификаторы переводить frontend-каталогом. Для настоящего справочного prose использовать существующий localized lookup + en fallback; кеш такого текста должен учитывать locale.

Только если нужны de-строки в существующих *_i18n: новая forward-only миграция со следующим свободным номером (на снимке последний 058), расширение CHECK только перечисленных существующих таблиц, не переписывать 017/018, seed-файл отдельно. Проверять ограничения PostgreSQL, SQLite это не докажет. Не создавать заново удалённые кэши и не переводить все исторические справочники без живого потребителя. База production в подготовке не инспектировалась; её фактические данные не считаются проверенными.

## 4. Порядок реализации: отдельные законченные этапы

### DE-1 — runtime, gates и базовый каталог

Файлы: i18n.js, locale.py, locale-formatters.js, locale-switcher.js, app-nav.js, inline preloader в forecast-new.html, consultation.js; четыре locale JSON; missing/untranslated checkers, i18n-known-issues.cjs, соответствующие тесты и CI.

Перевести текущие 2303 ключа по 31 пакету из translation-source.json; это входные данные, не новая runtime-структура. Закончить перевод и отдельную редактуру всех строк каждого пакета по COPY_GUIDE.md, прежде чем считать de готовым. Вести раздельные статусы translated/editorially_reviewed. Затем проверить связанные тексты целиком на экране и письма целиком; выборочная проверка нескольких фраз не считается редактурой каталога. Для временных промежуточных коммитов не объявлять полноту по fallback.

Расширить default locales и в run-функциях, и CLI checker. Тесты с временными en/uk/ru fixtures должны явно указывать old locale list либо создавать de. Не обходить проверку отсутствующего файла.

Untranslated checker требует per-locale исключений: `Saturn`, `Uranus`, `Neptun`/другие термины проверять по факту равенства, а не объявлять весь astro.* исключением. Законные совпадения вроде `Mars`, `Saturn`, `Pluto`, `Chiron`, `Orbis` (если en такой же), `Opposition`, `Status`, имена городов — точные ключи + причина + locale=de. Они не должны ослаблять проверки uk/ru. Поменять структуру allowlist минимально, сохранить совместимость текущих тестов/CLI.

Выход: немецкий доступен в обоих переключателях; корректен bootstrap; весь текущий каталог переведён; fallback проверен искусственно удалённым тестовым ключом.

## 7. Как экономно передать работу другой модели

Начать с IMPLEMENTATION_PROMPT.md. Выполнять этапы последовательно; не загружать весь translation-source.json и все bundles в один контекст.
